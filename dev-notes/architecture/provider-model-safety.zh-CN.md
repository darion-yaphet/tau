# 提供商/模型安全与 HTTP 错误详情

Issue #226 与 PR #249 修复的提供商/模型不匹配问题有所重叠：`/tree` 导航现在会保留当前运行时模型，而不是只重放所选分支中的历史模型。本文记录了此后增加的额外加固。

## 变更内容

- 在打印模式、TUI 启动、模型切换、提供商刷新或运行时提供商构造继续进行之前，提供商/模型选择现在会验证所选模型是否由所选提供商声明。
- 对于包含旧版持久化 `model_change` 条目且其已不再匹配当前提供商的会话，会回退到当前提供商配置的默认模型，而不是创建不匹配的运行时提供商。
- 只有当某个提供商当前可用时，TUI 恢复启发式逻辑才会根据保存的模型推断该提供商，因此具有相同模型名称但不可用的提供商不会意外胜出。
- OpenAI 兼容、OpenAI Codex 和 Anthropic 的 HTTP 错误现在共用一个辅助函数：它从 JSON 正文提取有用的提供商错误详情，并在用户可见的提供商错误消息中包含 HTTP 状态和所选模型。

## 存在原因

Tau 的提供商目录有意区分具体提供商：`openai` API 密钥提供商与 `openai-codex` 订阅提供商是不同的传输通道，可能不支持相同的模型。根据当前提供商验证模型，可将无效组合转化为即时、可操作的配置错误。

共享 HTTP 错误格式化器使生产环境故障在提供商因账户、模型可用性、请求形态或其他验证原因拒绝请求时仍可调试。对于不可恢复的提供商错误，编码会话诊断日志已经会记录提供商名称、模型、状态和安全的响应正文。
