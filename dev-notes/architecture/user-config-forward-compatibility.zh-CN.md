# 向前兼容的用户配置

## 变更内容

Tau 现在会忽略用户级运行时设置中无法识别的字段：

- `~/.tau/tui.json` 中的顶层设置和嵌套快捷键动作；
- `~/.tau/settings.json` 中的字段；
- `~/.tau/providers.json` 中的顶层设置和嵌套提供商偏好字段。

已识别字段仍与之前一样严格验证。已知值无效、对象格式错误、已知键字符串为空、shell 前缀别名冲突，以及已知 TUI 动作之间重复赋值，仍属于配置错误。

## 原因

这些 JSON 文件属于用户级状态，可能由多个 Tau 安装共享。较新的 Tau 发行版可能会添加某项设置，并将其写入其中一个文件。此前，启动旧版时可能会在打开 TUI 前失败，并显示如下错误：

```text
Unknown TUI settings field: turn_notification
```

现在，每个解析器只消费其版本能够理解的字段，并忽略未来元数据。这遵循会话索引记录（`extra="ignore"`）、凭据对象字段、未知顶层提供商设置和孤立提供商偏好已采用的兼容性原则。

未知字段不属于解析后的设置模型，因此如果该旧版本后来重写设置文件，也不会输出这些字段。此变更保护启动兼容性；它不会让旧版理解或保留较新的功能。

## 有意保持严格的格式

此策略并不适用于每个持久化文件：

- `~/.tau/catalog.toml` 仍按 schema 版本管理并保持严格，因为它控制提供商端点、身份验证路由、模型能力和定价；
- 自定义主题 JSON 保持严格，使拼错的颜色和角色名称产生有用诊断，而不是导致不易察觉的损坏主题；
- 会话对话条目保持严格，以保护对话完整性。

凭据对象和会话索引元数据本来就容忍额外字段，因此无需更改解析器。

## 测试方法

1. 向每个 JSON 设置文件添加一个虚构字段，例如 `"future_setting": true`。
2. 在 `tui.json` 的 `keybindings` 内添加一个虚构动作，并在某个 `providers.json` 提供商偏好内添加一个虚构选项。
3. 启动 Tau，确认 TUI 打开且已识别设置仍然生效。
4. 为已识别设置提供无效值，确认 Tau 仍会报告相应配置错误。

自动化测试覆盖三个解析器中的忽略字段，以及针对已识别字段的现有严格验证测试。
