# 动态提供商契约和分层注册表

## Phase 1 新增内容

Issue #605 实现了 #602 Phase 1 中与提供商无关的基础。它**没有**添加内置提供商、启动选择、`/local`、TUI 或任何 llama.cpp 行为。

新增部分包括：

- `extensions/providers.py`：不可变的提供商/模型/认证/传输/刷新契约；
- `extensions/provider_registry.py`：进程本地的持久/动态组合和刷新协调；
- `ExtensionAPI.register_provider(...)`：通过所属 `ExtensionRuntime` 路由的扩展注册；
- `create_dynamic_model_provider(...)`：使用 Tau 现有 OpenAI 兼容传输或扩展工厂构造候选运行时；
- 明确的 OpenAI 传输开关，防止动态模型名称通过启发式规则选择 `/responses`。

Phase 6 使用一个永久的第二虚假后端和一个仅用于测试的小型 Ollama 适配器验证这些 API。该适配器使用分离的提供商和本地状态端点，不向契约添加提供商专用概念。

## 动态提供商为何不是持久设置

Tau 现有的 `ProviderConfig` 对象描述从内置目录、`~/.tau/catalog.toml` 和 `~/.tau/providers.json` 加载的用户/应用配置。扩展注册具有不同的所有权：其代码来源和信任决策只存在于一个分阶段的运行时世代中。持久化该定义会使后续进程在来源消失后或获得信任前继续使用提供商行为。

因此，注册表接收完整的持久 `ProviderConfig` 对象作为不可变基线，并且从不序列化动态数据。每个动态层存储：

```text
provider id + source id + runtime generation id + layer id
```

最后一个活动注册胜出。对于已加载扩展，宿主从规范入口文件路径派生稳定的来源 ID；扩展显示名称从不用于确定提供商所有权。加载器会在导入任何扩展之前冻结每个发现的 ID，并将其存储在 `LoadedExtension` 上。因此，即使导入/设置代码重新定向入口符号链接或其祖先，也不会改变重复检测、API 注册或设置失败后的清理所有权。即使在不同信任阶段加载，名为 `shared.py` 的不同路径也会获得不同层。同一运行时中重复的规范入口按首次加载优先级忽略；新的运行时世代可再次加载该稳定来源。同一来源注册同一提供商会原子替换该来源的旧层。移除它会显露之前完整的动态层；移除最后一层则会返回完全相同的原始持久对象，包括请求头、模型元数据、兼容性、超时、重试、思考配置和所有其他字段。工具和命令仍使用彼此独立、首次注册胜出的名称注册表。

本阶段有意不提供通用的快照磁盘存储。未来可信的内置功能可以拥有版本化、白名单式的安全缓存，但公共扩展存储需要单独的来源身份和信任设计。

## 提供商和模型验证

一个 `DynamicProvider` 具有非空且精确的 ID/显示名称、零个或多个具有唯一 ID 的 `ProviderModel`、一个可选默认模型（必须属于当前完整快照），并且只能有一种运行时机制：

1. `OpenAICompatibleTransport`；或
2. 自定义运行时工厂。

零模型是有效状态：它表示休眠提供商，无需虚构模型。未知模型元数据保持 `None`；空元组表示“已知为空”。兼容性数据会被复制、通过 JSON 验证并深度冻结：嵌套对象变为只读映射，数组变为元组。因此注册表视图、刷新结果和回调 `cached_models` 可以共享同一个已验证模型值，而不会让消费者修改活动状态。运行时构造会在传输边界将兼容性数据转换回新的普通 JSON 字典/列表。运行时请求头会被复制，但从表示中排除，也没有持久化辅助函数。

构造过程会在修改注册表前验证整个候选对象。因此，无效的同来源替换或刷新会保持先前的层/快照不变。

## 认证和机密处理

动态认证只会在刷新或创建候选运行时前解析：

```text
RequiredApiKey / OptionalApiKey
  → Tau credential reader
  → configured environment variable
  → missing result

NoAuth
  → consult neither source
```

必需认证缺失时会失败并提供设置指导。缺少可选认证以及 `NoAuth` 会产生 `omit_authorization_header=True`；不会使用虚假的 `Bearer local` 值。解析后的 key、认证请求头和扩展提供的认证来源都只是运行时字段，并从 `repr` 中排除。传输/模型请求头同样排除。静态传输/模型请求头不能提供 `Authorization`；Bearer 或自定义授权必须在解析时来自认证策略。这可以防止凭据成为已注册定义的一部分，同时仍允许通过解析后的认证请求头使用非 Bearer 方案。刷新诊断从不包含扩展异常字符串或解析后的认证数据，因为两者都可能含有请求数据或机密；诊断只报告有界类别和来源 token。运行时创建同样会将自定义认证解析异常转换为分类式宿主错误。只有 Tau 精确的 `RequiredApiKey` 策略会保留宿主生成的缺少 key 设置指导。

## 刷新生命周期

刷新回调接收：

- 一个取消 token；
- 是否允许使用网络；
- 当前安全的内存模型元组；
- 已解析的认证。

它返回一个完整的 `ProviderModelSnapshot`。协调器会：

1. 识别精确的有效来源/层/世代 token；
2. 只在 token 与 `allow_network` 策略均匹配的调用者之间共享一个任务；
3. 在保护兼容共享工作的同时，为每个调用者应用自己的超时；
4. 验证返回的完整快照；
5. 同步重新检查来源、层、世代和操作修订版本；
6. 仅在所有权全部匹配时发布。

相反的网络策略使用不同的发现任务，因此禁止联网的调用者不会消费允许联网的发现结果，而稍后的联网调用者仍可执行网络工作。短等待者可以超时而不终止与较长等待者兼容的工作。当最后一个等待者超时，或 `cancel_refresh` 取消操作时，合并条目会在该调用者返回前同步分离。因此立即重试会创建新操作。每个完成回调携带旧操作身份，所以它无法移除在相同键下创建的后继操作。分离的工作继续保存在单独的自有操作集合中，直至真正完成。

超时、显式取消、来源替换、取消注册、重新加载和运行时退役都会发出信号并取消自有工作。调用者取消受到保护，因此一个等待者无法破坏其他等待者共享的工作。发现最多只会收到一次 `Task.cancel()` 请求。异步关闭会等待回调退出，或从该请求发出起最多等待 0.25 秒；它不会仅因清理超过 0.1 秒就在普通 `finally` 块中注入第二次取消。在遏制时间内完成的清理，会在重新加载、替换、重置关闭或最终关闭返回前排空。

在 0.25 秒时仍运行的回调会被归类为**已遏制**，而非已排空。`ProviderRegistryCloseResult(drained=False, contained_discovery_tasks=...)` 会报告这一精确状态。进程拥有的监督器会强引用发现任务，而任务的完成回调会保留其已退役世代注册表，直至真正完成。这个显式根可避免会话丢弃旧运行时后依赖 asyncio 的弱任务引用。外层操作结束后，回调不再有发布路径，而来源/层/世代/修订防护仍然有效。失败工作保留当前快照，每个层 token 最多记录一条诊断；注册表还会应用全局上限。

## 运行时创建和传输路由

OpenAI 兼容的动态提供商复用 `tau_ai.OpenAICompatibleProvider`。传输请求头、模型请求头和解析后的认证请求头只在内存中合并。缺少可选认证时，会传入空的内部 key 和 `omit_authorization_header=True`，因此 HTTP 适配器不会发送 Authorization 请求头。

仅当 `stream_response` 和 `aclose` 都可调用时，才接受自定义运行时工厂。被验证拒绝的已构造候选对象会尽可能恰好关闭一次；关闭错误会被遏制，不能取代分类式配置错误。

现有适配器过去会为一些类似 OpenAI/Codex 的模型 ID 推断 `/responses`。对于持久提供商，这仍是兼容性默认行为。动态传输描述符明确拥有自己的 API 选择，并设置 `infer_api_from_model=False`；因此当 `api="openai-completions"` 时，名为 `gpt-5.4-local` 或 `my-codex-local` 的本地模型仍会访问配置的 `/chat/completions` 端点。

## ExtensionRuntime 所有权

现在每个 `ExtensionRuntime` 都会创建一个提供商注册表，其显式世代身份与自身 `ExtensionGeneration` 相同。加载器在导入任何扩展前，通过 `Path.resolve().as_uri()` 为每个发现的入口分配来源 ID，将该值存储在 `LoadedExtension` 上，此后只使用已存储的 ID。`register_provider` 使用该宿主拥有的 ID。显示名称仍然只是面向用户的标签。

如果 `setup()` 抛出异常，运行时只移除携带该精确已存来源 ID 的注册，包括提供商、工具、命令、指南、渲染器和事件处理器。因此，一个失败的第二个 `shared.py` 无法移除来自另一条路径且已成功加载的第一个 `shared.py`；成功的同名提供商会作为正常的独立层进行遮蔽和恢复。重复工具和命令仍按名称忽略，因此首次注册语义不变。

重新加载和退役会在使旧 API 失效前取消注册表工作并移除层。`CodingSession.reload()` 和目标替换会同步发布新状态，然后在独立拥有的任务中关闭旧运行时。在这个已提交的接缝处发生的取消会被遏制，直至清理排空或报告有界的恶意工作；操作返回已采用的结果，而不会声称回滚。最终的 `CodingSession.aclose()` 同样拥有一个持久关闭任务，但只有在扩展注册表和每个提供商账本条目都收到一次关闭尝试后，才传播观察到的调用者取消。重复关闭会观察同一个任务，不能关闭提供商两次。分阶段替换会在旧对象关闭、新对象启动和所有其他发布前接缝中明确拥有候选提供商账本。取消或失败时，会在传播前关闭该候选会话，同时保持活动提供商开启；成功时只将账本转移一次给存活的外层会话。`reset_for_reload()` 是同步的，因此会为运行时稍后的异步关闭保留每个已退役注册表。已遏制任务通过其完成回调与已退役注册表一起由进程监督，不会被错误标记为已排空。重新加载随后会基于同一个不可变持久基线创建新的世代和空注册表。提供商刷新诊断会投影为普通运行时诊断，但不会暴露机密。

## 验证方法

聚焦测试覆盖休眠/无效契约、认证优先级与省略、机密安全表示、精确持久恢复、多来源优先级、同来源替换、同名不同路径及符号链接重新定向隔离、完整的失败设置清理、策略安全且立即重试安全的刷新合并、每等待者超时、单次取消的协作式清理、显式恶意工作遏制、发布前候选中止、发布时取消的生命周期排空、最终关闭/提供商账本清偿、格式错误的输出、过期工作、深度不可变性、被拒运行时清理、认证异常脱敏、不进行持久写入、退役、HTTP 认证请求头和模型名称路由：

```bash
uv run pytest tests/test_extension_providers.py tests/test_extensions.py \
  tests/test_provider_config.py tests/test_provider_runtime.py tests/test_http.py
uv run ruff check .
uv run ruff format --check .
uv run mypy
```
