阶段 23 改进 Textual 前端，同时让可复用代理 harness 继续独立于 UI 事项。

边界仍为：

```text
CodingSession emits AgentEvent values
        ↓
TuiEventAdapter updates TuiState
        ↓
Textual widgets render the transcript and controls
```

## 当前完善切片

实时工具结果现在会在对话记录中渲染成功输出的预览，与恢复的会话历史一致。TUI 显示前几行，
并在隐藏更多内容时显示预览提示，因此大型 `read` 或 `bash` 结果不会淹没对话，而持久会话仍为
模型上下文和重放保留完整工具结果。

对话块现在会在同一组 Pi 风格堆叠消息块内，使用 Rich 语法渲染器显示围栏代码和持久化编辑补丁。
对话状态仍只存储普通角色/文本项；这只是 Textual 前端的渲染改进。

对话表面现在是由可选择消息组件组成的滚动容器，而不是一个大型 `RichLog`。每个消息组件负责提取
自身渲染块中的选中文本，因此鼠标局部选择会限制在目标消息中，复制相邻消息时不会意外扩展到完整对话。

助手对话块现在也通过 Rich Markdown 渲染标题、项目符号、引用块、链接、行内代码和强调等常见
Markdown 结构。用户、工具、状态和错误块保持原样显示，除非由显式代码或补丁渲染器处理；这使粘贴的
提示词和工具输出保持可预测。

实时 `edit` 工具结果现在在工具块中包含统一补丁。这为文件编辑提供内联 diff 视图，同时保持事件
适配器与 Textual 组件解耦。工具结果元数据现在保留在 `ToolResultMessage` 中，因此恢复的会话历史
可以根据持久化 JSONL 条目渲染相同的编辑补丁块。

TUI 还提供命令面板入口。按 `Ctrl+K` 会聚焦提示框、插入 `/`，并使用现有补全引擎显示全部斜杠
命令补全。选择使用与普通斜杠命令自动补全相同的 `Tab`、`Up` 和 `Down` 绑定。当高亮补全项会改变
提示词时，按 `Enter` 会应用补全而不提交提示词，与常见终端选择器行为一致。

斜杠命令输出现在属于临时 UI，而不是对话内容。简短命令结果使用 Textual 通知，多行输出（例如
`/help`、`/skills`、`/resume`、`/status`、`/resources` 和 `/context`）会打开可关闭模态框。
这让命令参考资料不进入代理对话，同时仍可访问相关信息。

同一补全引擎现在会为 `/model` 和 `/login` 参数建议可用值。`/model` 还可以为已配置的提供商/模型
选择打开模态选择器，而 `/login` 仍用于添加提供商。

提示框也会为 `/resume <session-id>` 建议已索引的会话 ID，普通 `/resume` 会打开与会话选择器
快捷键相同的模态会话选择器。这些行包含标题、模型和工作目录等会话元数据，并保持 `SessionManager`
中当前项目的最新优先顺序。提交命令会通过 `CodingSession` 重新加载所选会话，并原地重建可见对话。

TUI 还有一个小型模态会话选择器，默认绑定到 `Ctrl+R`。它使用恢复补全相同的元数据列出已索引会话，
然后通过 `CodingSession.resume()` 恢复所选会话。选择器完全位于 Textual 前端；可移植 harness
仍没有会话选择策略。

内置 Textual 前端现在会读取 `~/.tau/tui.json` 中的可选按键绑定设置。用户可以重新映射命令面板、
补全导航、会话选择器、取消和退出按键，同时配置留在 `tau_coding.tui`，而非可复用代理 harness。

同一 TUI 设置文件现在支持具名内置主题。`tau-dark` 仍是默认主题，`high-contrast` 提供更明亮的
深色调色板。默认主题受 Toad Textual UI 启发：更深的表面、透明装饰、柔和分隔线、底部聚焦提示框，
以及带细左侧强调线而非盒状卡片的堆叠对话行。主题选择会同时注入 Textual CSS 变量和 Rich 对话/
侧边栏渲染器，因此应用装饰和消息块保持视觉一致，又不会向 `tau_agent` 加入 UI 策略。

侧边栏现在支持响应式布局。在中等或更大的终端窗口中保持可见；终端过窄或过矮时自动隐藏，为对话和
提示框保留足够空间。可见性规则位于 Textual 前端；会话元数据和代理状态不变。显示时，侧边栏会列出
已加载的上下文文件，因此无需另开命令模态框即可检查 `AGENTS.md` 等项目指令。

状态行现在会在运行期间显示小型动画活动指示器，并在运行完成、取消或失败后恢复为 `Ready`。它也会在
排队提示词等待注入时显示待处理的 steering/follow-up 队列数量。

思考控件现在包含两种不同 TUI 行为：当前提供商/模型支持时，`Shift-Tab` 循环切换当前思考模式；
`Ctrl-T` 切换流式思考 token 的显示。思考 token 对话块默认隐藏，显示时使用独立角色样式。

模型控件现在包含 Pi 风格的范围模型流程。`/model` 仍打开提供商/模型选择器，但 `Space` 会切换
高亮模型是否加入持久化范围列表，`Tab` 会在全部模型和范围模型间切换选择器。`Ctrl-P` 可直接从
提示框循环切换范围列表。TUI 请求 `CodingSession` 更改和循环该列表；Textual 不自行读写提供商设置。

活动指示器现在位于提示框正上方的稳定行，而不是顶部状态行。这让代理轮次运行时底部输入区保持明显的
活动状态，并让顶部状态区专注于提供商、模型、队列和会话状态。

Textual 页脚现在通过普通可见绑定显示 Tau 的快捷键提示。它描述当前的提交、换行、选择器、思考、
follow-up 和清空提示词快捷键；补全打开时切换为补全相关绑定，代理轮次运行时再次切换。Tau 不添加
独立自定义提示行；内置底部工具栏仍是唯一快捷键界面。

TUI 将 `Esc` 视为两步取消流程。第一次按键通过 `CodingSession.cancel()` 请求优雅取消，并让当前
工作线程保持可见，等待提供商或工具观察取消 token。第二次会立即中断当前 Textual worker。这与 Pi
的取消边界一致：UI 代码请求取消，可移植代理循环携带取消 token，`bash` 等长时间工具遵守该 token，
而不会让 Textual 成为 `tau_agent` 的依赖。由于取消是有意的用户操作，内置 TUI 将最终取消事件
渲染为状态文本，而不会向对话添加错误行。

助手代码块渲染现在更具防御性。已知围栏语言使用 Rich/Pygments 语法高亮，未知或自定义围栏标签则
回退为普通代码渲染，避免产生损坏的对话块。

内置主题集现在除 `tau-dark` 和 `high-contrast` 外还包含 `tau-light`。主题选择仍位于
`tau_coding.tui` 配置，并注入 Textual CSS 变量和 Rich 渲染器，不让 UI 策略泄漏到可移植 harness。
Textual 原生主题注册表也限制为这些 Tau 主题，因此 Textual 菜单/命令面板中的主题项会更改 Tau 的
持久 `~/.tau/tui.json` 设置，而不会形成第二套非持久主题系统。

现在可以在 TUI 中通过 `/name <new name>` 重命名会话。该命令更新 `/resume`、恢复补全和会话选择器
使用的已索引会话元数据；底层只追加对话记录仍是对话事件的持久来源。

前端边界现已记录在[构建自定义 TUI](../custom-tui.md)中。该指南说明其他终端 UI 如何消费
`CodingSession`、`AgentEvent`、`TuiState` 和 `TuiEventAdapter`，而不与 Textual 内部实现耦合。

## 手动验证清单

这些检查会在 Textual TUI 中验证阶段 23 的完善内容。请使用位于 `origin/main` 的干净工作树，
避免本地实验分支影响结果：

```bash
git fetch origin
git worktree add /tmp/tau-tui-validate origin/main
cd /tmp/tau-tui-validate
uv run tau
```

1. 启动会话并运行 `/name Manual validation`，然后打开 `/resume`，检查 `/name`。重命名后的会话
   应出现在恢复选择器和 `/resume <session-id>` 补全中。
2. 提交一个需要几秒的提示词，检查工作指示器。轮次运行时提示框边框应在活动颜色间缓慢渐变，且提示框
   上方不应有独立 spinner 行。
3. 检查内置底部页脚的快捷键提示。它应显示提交、换行、命令、会话、思考、清空和退出等提示操作。
   打开斜杠命令自动补全，确认同一页脚切换为完成、选择和关闭操作。提交一个需要几秒的提示词，确认
   页脚切换为 steer、follow-up、取消、思考和工具操作。页脚上方不应有第二个自定义快捷键行。
4. 请求模型提供一个围栏 `python` 代码块和一个使用未知语言（如 `not-a-real-language`）的围栏块，
   检查代码块渲染。Python 块应高亮，未知语言块应显示为普通代码，且不会破坏对话记录。
5. 写入以下文件以检查浅色主题：

   ```json
   {
     "theme": "tau-light"
   }
   ```

   将其写入 `~/.tau/tui.json`，重新启动 `uv run tau`，确认应用使用浅色调色板，且对话、侧边栏、
   页脚和提示框颜色清晰可读。检查后恢复你偏好的主题。

## 边界

这些变更位于 `tau_coding.tui`。命令注册表仍负责命令元数据，`tau_agent` 仍不了解 Textual、
按键绑定、斜杠命令和渲染。
