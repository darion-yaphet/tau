# `/resume` 后台加载

## 变更内容

TUI 现在会先挂载一个空的 `/resume` 外壳，然后在后台线程中读取当前项目和其他项目的索引。已打开的选择器会显示分阶段加载消息并保持可用；当前项目的会话先出现，随后完整项目列表出现，期间不会替换模态框。

选择器的两列都使用 Textual 的虚拟化 `OptionList`。此前，每个会话和项目都会成为已挂载的 `ListItem`，尽管模态框最多只显示 16 行。因此，大型历史记录在构造部件上花费的时间远多于解析索引。`OptionList` 保留每个可搜索选项，但只渲染可见行。

普通 `/resume` 命令补全在输入命令名称本身时不再读取会话索引。当 `/resume ` 后存在参数文本时，仍可补全会话 ID。

## 原因

同步聚合每个 `~/.tau/sessions/*/index.jsonl` 文件会在模态框出现之前阻塞 Textual 事件循环。急切挂载数百个行部件会增加更大延迟。将跨项目文件系统和 Pydantic 工作移出事件循环，并对两列进行虚拟化，使常用的当前项目路径可立即使用，同时保留跨项目发现和搜索。

## 安全性与行为

- 全局后台失败时，已加载的当前项目会话仍可使用，并显示警告。
- 如果选择器已关闭或被替换，结果会被忽略。
- 当相应记录仍存在时，刷新会保留所选项目、搜索查询和所选会话。
- 会话管理器和可移植 Agent harness 仍独立于 Textual。

## 验证

一个 Textual pilot 测试会阻塞全局索引读取，验证模态框和本地会话已经可以交互，然后释放读取并验证其他项目出现。现有的选择器导航、搜索和恢复测试覆盖刷新后的列表。
