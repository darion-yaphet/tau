# 项目信任运行时

Issue #535 在 `tau_coding` 中为环境项目资源增加了输入加载防护。已接受的策略与 Pi 兼容性研究仍保存在 `dev-notes/design/project-trust.md` 中。

## 运行时形态

- `project_trust.py` 负责类型化的请求/解析结果、严格的 cwd 规范化、仅元数据检测、优先级、按 cwd 缓存，以及带锁的版本 1 原子存储。
- `TauResourcePaths.project_resources_enabled` 创建统一一致的资源计划。现有技能、提示词、上下文、系统提示词、主题和扩展加载器使用该计划，而不是自行实现策略。
- `CodingSession.load` 首先只导入用户扩展/显式扩展，解析信任状态，然后加载受保护的 Markdown/JSON 和已选择启用的项目扩展。
- CLI 入口点提供用户全局默认值和本次调用覆盖值。结构化/无头模式不显示提示。TUI 将与前端无关的请求适配为无障碍的 Textual 模态框。
- 重新加载和目标位置替换会先暂存绑定到新 cwd 的扩展运行时、资源、工具、命令、提示词和信任缓存条目，然后再采用。资源计划始终重新绑定到规范化后的目标位置；源项目注册内容绝不会跨越 cwd 边界。取消或任何准备失败都会保留当前快照和之前的协调器缓存。

`tau_agent` 不依赖信任、路径、Typer 或 Textual。Textual 仍位于 `tau_coding.tui` 中。

## 持久化与失败行为

`~/.tau/trust.json` 包含 `version` 和排序后的 `decisions`。读取时会拒绝未知字段/版本、重复路径、相对路径、未规范化路径以及未知值。更新时会锁定存储，并首先持久安装一个权限模式为 0600 的撤销日志；随后写入同目录临时文件并执行 fsync，再替换 `trust.json`，最后对目录执行 fsync。读取器会拒绝任何存在待处理日志的存储。只有在目标提交点之后才会删除日志；失败时会尝试恢复，而恢复失败则保留日志，因此即使提交和恢复同时失败，也不会暴露新授予权限的字节。日志清理的 fsync 失败在两种持久化结果下都是安全的：已提交的存储保持可见，或者日志重新出现且读取失败关闭。错误会被诊断并以关闭方式失败；仅本次运行的显式批准不依赖存储。

## 迁移

不存在旧版存储。现有项目不会被自动信任。存在受保护候选项时，交互式用户自行决定；无头模式下未解析的 `ask` 会跳过项目输入。用户/全局资源和显式 CLI 资源继续加载。`--project-extensions` 仍是额外的可执行代码选择启用项。

## 验证

使用临时主目录/项目以及伪扩展/提供商。运行：

```bash
uv run pytest
uv run ruff check .
uv run ruff format --check .
uv run mypy
cd website && hugo --minify
cd website && npx --yes pagefind@latest --site public
```

项目信任不是文件系统/进程/网络/工具/模型沙箱。
