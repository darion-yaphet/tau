# 自动会话命名

Tau 会根据第一条用户消息，自动为新建的托管会话生成一个简短标题。

## 新增内容

- 第一条用户消息被持久化保存后，新建的托管会话会自动命名。
- Tau 会请求当前选中的提供商/模型生成一个不超过四个词的简洁标题。
- 标题写入会话元数据前会先经过清理。
- 如果提供商调用失败或返回的文本不可用，Tau 会回退到根据第一条消息在本地生成标题。
- `/name` 仍可用于手动覆盖，Tau 不会替换已有的会话标题。

## 存在原因

会话 ID 适合精确引用，但在 `/resume`、`tau sessions` 和 ID 补全中很难快速浏览。自动命名让已保存的会话更容易识别，用户无需暂停当前工作并逐一手动命名。

## 与 Pi 的区别

这是 Tau 有意偏离 Pi 极简基线的少量产品设计之一。Pi 风格的会话持久化侧重持久的对话记录和明确的用户操作。Tau 增加了自动会话元数据，以改善恢复和发现工作流。

这一差异保留在 `tau_coding` 中，因为它属于应用元数据行为，而不是可复用的代理框架行为。`tau_agent` 仍然只负责可移植的代理循环、消息、工具和事件。

## 模型选择

Tau 使用会话当前选中的提供商/模型来处理命名请求。目前还没有单独的标题模型设置。这样既能保持实现简单，又能遵循活动会话的配置；但这也意味着第一轮可能会在主要助手响应之前额外发起一次简短的模型调用。

## 持久化行为

只有第一条用户消息被持久化之后才会执行命名。这保留了新准备会话的延迟索引行为：如果会话在第一条持久消息写入前被取消，不应仅仅因为命名已经开始就出现在恢复索引中。
