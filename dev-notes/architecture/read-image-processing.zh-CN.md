# 有界的读取图像处理

## 新增内容

`read` 工具现在会先用 Pillow 验证图像字节，再进行附加。它接受从文件内容检测出的 JPEG、静态 PNG、GIF、WebP 和 BMP。由于提供商 API 对 BMP 的支持并不一致，BMP 会被标准化为 PNG。任一边超过 2,000 像素或大小超过 5 MB 的图像会被缩放并重新编码；宽高比保持不变，小图像绝不会被放大。

处理过程有明确上限：

- 源编码：50 MB
- 源尺寸：4,000 万像素
- 输出尺寸：最大 2,000 × 2,000
- 输出编码：5 MB
- 图像头探测：加载超大本地文件前读取 64 KB
- 缩放/编码尝试：12 次

选择 Pillow 是因为它提供维护良好的跨平台 wheel，支持所需格式，并提供解码验证和解压炸弹警告。Tau 会将这些警告及解码/编码失败转换为纯文本工具结果。在 Pillow 的元数据 API 允许时，会在加载像素数据前检查限制。对于默认本地操作，超过 50 MB 的文件会通过 64 KB 前缀分类，已知图像系列会在读取完整文件之前被拒绝。大型文本文件保持现有读取行为。

`ReadOperations` 将路径验证和字节读取同工具的分类及处理分离。可选的大小和前缀回调支持提前拒绝图像；未提供这些回调的实现仍保留完整读取的回退路径。默认实现仍是本地文件系统。测试可以提供伪操作，未来的远程文件系统集成也可如此实现，无需把本地 I/O 移入 `tau_agent`。

## 存在原因

首个多模态实现能够在 Agent 和提供商层之间正确传递规范的 `ImageContent`，但会拒绝每个超过 5 MB 的附件，并信任浅层签名。真实截图和相机图像可能超过提供商限制，但仍很容易缩放。格式错误或解码后非常大的图像也需要可预测的失败行为。

这遵循 Pi 的分层：编码特有的文件/图像工作发生在读取工具边界，`tau_agent` 存储与提供商无关的内容，`tau_ai` 负责序列化。Tau 保留 `tau_ai/content.py` 中现有的共享能力辅助函数；提供商适配器仍负责各自线协议中的放置方式，因为工具结果图像在不同 API 中的位置不同。

## 产品与交付决策

1. 已经安全时保留原始受支持字节。这可避免质量损失，并保留受支持的 GIF/WebP 动画。
2. 将 BMP 转换为 PNG，并缩放静态超大图像。超过限制的动画图像会被省略，而不是静默压平为单帧。动画 PNG 和 JPEG XL 输入会收到明确的不支持格式说明，而不会继续尝试 UTF-8 解码。
3. 在 `ImageContent` 中只保留一个转换后的负载。原始字节和 base64 不会复制到工具 `details` 或会话 JSONL 中。
4. 在 `CodingSession` 与内置 `read` 工具之间共享可变的图像能力状态。纯文本模型会在图像处理前收到醒目的纯文本说明，模型变更会原地更新该状态。提供商适配器对旧会话和其他工具保留相同的防御性降级。
5. 向模型返回转换说明，让它知道尺寸或编码何时发生了变化。
6. 终端图像渲染不在范围内。Textual 没有与 Pi 终端图像协议渲染器等效的内置功能，因此 TUI 继续显示文本状态。可以单独评估自定义部件或第三方集成，而无需更改工具结果契约。
7. 实时凭据检查不纳入 CI。`TODO.md` 保留提供商/模型验证矩阵的后续事项。

## 测试方法

针对性行为：

```bash
uv run pytest tests/test_image_processing.py tests/test_coding_tools.py
```

完整验证：

```bash
uv run pytest
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv build
cd website && hugo --minify
```

手动验证时，应使用视觉模型读取一张小图像、一张 BMP，以及一张超过 2,000 像素的静态图像。确认模型能看到每张图像，BMP 被报告为已转换，大图像会报告缩放后的尺寸。
