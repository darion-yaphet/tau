# 《从终端到智能体：用 Tau 理解 Agent 架构》系列目录

面向想把 Agent 从“会说话的黑盒”拆开的开发者。这不是功能清单，也不是产品手册。系列顺着一次用户请求从进到出的路线，解释一个能干活的 Agent 为什么需要边界、状态和反馈回路。

每篇只攻一个问题。三层分工只在第 0 篇摊开全图，后文用一句话回指，不再整段重演。

**前置知识：** 读者最好会读 Python 异步代码（async/await、异步迭代器），知道 SSE/JSON 流式的基本概念。不假设读过 Pi 的源码，但知道“Pi 是 Tau 对标的极简编码 Agent”会有帮助。

**版本快照：** 本系列基于 Tau 0.4.1（2026 年 9 月）源码写成。Tau 演进很快，文中函数名与行级细节以仓库当前源码为准；设计原则部分变化慢得多。

## 0. Tau 是什么：给初学者的终端 Agent 全景图

- Tau 作为终端编码 Agent，实际能做什么、不能替您决定什么
- 模型、Agent、工具与终端界面分别扮演什么角色
- 为什么 Tau 同时是可用产品和可供解剖的参考实现
- 一次简单请求会经过哪些环节，不进入函数级细节
- 如何阅读本系列：下一篇从两行 CLI 代码开始

## 1. 从一句话到一次行动：先建立 Tau 的 Agent 心智模型

- print mode 为什么消费事件流，而不是等待最终字符串
- `CodingSession.prompt()` 在把输入交给 Harness 之前做了哪些应用层准备
- `AgentHarness` 保存什么状态，工具循环在哪
- 若跳过这一层，直接调模型，会丢掉什么
- 附真实运行切片（notes/assets/run-slice/）供离线核对

## 2. 模型不是 Agent：tau_ai 如何统一不可靠的外部智能

- Provider 层为什么必须独立于 Agent 核心
- 流式文本、思考内容、工具调用与完成信号如何变成统一事件
- 重试、跨 Provider 历史和 Fake Provider 分别守住哪条边界
- 若把网络细节写进对话历史，下一轮会怎样

## 3. Agent 的大脑：Harness、消息与事件契约

- `AgentHarness` 如何把 Provider、system prompt、工具和状态组合成可复用运行时
- Message、Content 与上下文：模型实际看到了什么
- 为什么事件流比 UI 回调更适合作为系统契约
- 重叠 prompt 与取消后的悬空 tool call：状态机必须自己管，不能交给界面

## 4. 让模型行动：工具循环、反馈与安全边界

- Agent loop 的基本闭环：推理 → tool call → tool result → 再推理
- `read`、`write`、`edit`、`bash` 在系统中扮演的角色
- 工具失败为什么要成为模型下一轮推理的输入
- `cwd` 不是沙箱；能执行不等于该执行

## 5. Agent 为什么能持续工作：上下文、记忆与会话树

- 区分短期上下文、持久历史与用户可恢复的会话
- Context window 的成本与限制：为什么对话变长会让 Agent 退化
- 手动压缩、自动压缩与上下文溢出后的恢复策略
- JSONL 追加式历史、会话分支：压缩改变重放形状，不改写原始记录

## 6. 从大脑到产品：CodingSession、CLI 与可替换的 TUI

- `tau_coding` 如何把通用 Harness 放进真实的编码环境
- 启动阶段发生什么：项目目录、资源、`AGENTS.md`、`.tau/` 与 `.agents/`
- CLI、print mode、Rich/JSON/transcript renderer 如何消费同一事件流
- 若 TUI 自己再实现一遍 loop，会拆掉哪条边界

## 7. 让 Agent 可演进：扩展、可观测性与测试方法

- 扩展系统如何增加 Provider、工具或事件消费者，同时不侵蚀核心边界
- 生命周期、取消、重载与资源所有权
- 用事件、transcript 和 JSON 输出建立最小可观测性闭环
- 如何用 Fake Provider、Fake Tool 测试工具循环、错误恢复、会话与取消语义
- 回到 Tau 的设计取舍：先让一次请求的状态可信，再往上长

## 8. 从能跑到可信：trust、本地推理、成本与 RPC

- 项目 trust 是输入加载守卫，不是沙箱；与 Pi 的三处有意差异
- 模型的三个来源：models.dev 目录、Codex 订阅活目录、llama.cpp 本地推理走扩展接缝
- prompt caching、用量记账与响应计时：成本是会话事实，不是事后报表
- RPC 作为第三个前端：互换发生在进程边界，不在会话文件
- 与 Pi 对齐到哪、差在哪：一张对照表

## 推荐阅读节奏

第 0 篇给产品和概念地图；第 1–2 篇进入运行路径和模型边界；第 3–5 篇解释 Agent 的核心闭环与状态；第 6–8 篇落到产品适配、扩展、验证与长期可信。每篇用 Tau 的一段运行链路把设计摊开，再收成能搬到别的 Agent 项目里的原则。需要动手时，文中的反例都可以对着仓库里的测试或那两行 CLI 代码核对。每篇末尾的“三分钟核对”可以离线完成，不需要配置真实 Provider。
